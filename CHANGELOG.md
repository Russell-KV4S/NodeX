## 2026-11-20: 1.25 / code 27: hear nodes over the car radio, no automatic mute, false-RX hardening, private card title

- **New option: "Android Auto: hear nodes over the car radio"** (Settings, Android, off by default, both editions; owner request). While the car plays its own radio, satellite or another app, node audio plays on the navigation stream and NodeX holds navigation-style "may duck" focus while an unmuted node is heard, so the car turns the radio down for the node and back up 1.5 s after it stops. When NodeX is the car's source nothing changes. Core rules `CarRadioMix` / `RadioDuckGate` (10 new tests, 790 Core total); Android `AndroidRadioDucker` in the foreground service, `CarSession.HasCarAudio` from the car media service. **Not tried in a car**; it assumes the car's radio reaches the phone as a permanent audio-focus loss.

- **Nothing mutes automatically (owner: "unless I press I really don't want anything muted"):** the Android car/media service used to mute every node on a media Pause/Stop, on a navigation prompt or call, and when another app took the audio. Android Auto and Bluetooth stereos send Pause/Stop on their own, so nodes ended up muted with no press. Now Pause/Stop are ignored, Play only takes the car audio back (no unmute), and audio-focus changes don't touch mute. Car transmissions are still released on any media button or focus loss. Only the Mute buttons mute. Node audio now keeps playing through a phone call in the car; not tested in a car.

- **Private link cards drop the host:** the linked-node card and top-bar chip now show `1993 · 310108` (or `Node 1993`) with the PRIVATE pill instead of `1993 @ ysf.alert-alabama.org · 310108` (owner request with a phone screenshot). The host is still in the log and the Private Nodes screen.
- **False RX (owner report: occasional green on a node with nothing heard):** the log the owner sent has no KEY lines in that window, so any green there came from the "voice frames without KEY" rule. That rule lit a node on any voice frame, silent ones included, and every reconnect forgot that a hub sends KEY. Now only frames with sound count (`RxActivity.HasSound`, peak above about -50 dBFS), known KEY senders are remembered across reconnects, and Detailed logging writes `[rx] node N: receiving by voice frames without KEY` when a node lights without KEY. The exact node behind the report is not confirmed.

## 2026-11-19: 1.21 / code 23: links refused on carrier NAT ("does not match link IP"); lapsed registration

Field report: Tom (node 41603, NodeX on 5G) could not link to 41605/41604. The far nodes logged `Node 41603 IP 74.254.145.15 does not match link IP 74.254.149.17` (app_rpt drops a caller whose IP differs from the registered one) and, at other times, `Reported node 41603 cannot be found` (registration had lapsed while the badge still said "ASL Registered").

- **One shared UDP socket for calls and registration** (`Iax2Endpoint`). Every call now runs on it (`Iax2Session(Iax2Endpoint)`; distinct call numbers; datagrams dispatched by sender, unknown senders dropped), and the node **registers over IAX2** (`Iax2Registrar`: REGREQ/REGAUTH/REGACK, like an Asterisk `register =>` line) from that same socket, so the registry records exactly the public address the calls leave from. Before, registration went over HTTPS (TCP) and each call had its own UDP socket, and a carrier NAT can give each a different public address. New setting `IaxRegistration` (default on; no UI) replaces the old experimental `UdpRegistration`. `FallbackRegistration` switches to HTTPS if IAX2 never gets an answer (two attempts) or is rejected on this network; only one of the two runs at a time. A network change opens a fresh socket and restarts registration on it; calls on the old socket keep it until they end.
- **Registrar hardening:** each request is re-sent twice before counting as "no reply", one unanswered attempt is tolerated while registered, quick doubling retry after no reply, a background loop with out-of-band refresh like the HTTPS one.
- **Re-register before dialling** when the registration has lapsed, or (IAX2) is older than 20 s (`ReconnectPolicy.PreDialRegistrationAge`), waiting up to `RegistrationWait` (5 s). This brings back a short pre-dial wait in those cases (typically a few hundred ms), unlike the 15 s settle wait removed in 1.18.
- **NAT keep-alive:** while registered over IAX2, a STUN request every 25 s keeps the socket's carrier mapping (and so its public address) alive between registrations; if the public address changed anyway the node re-registers at once.
- **Network check** (`NetworkCheck`): after the first registration on each socket, two STUN servers (Google, Cloudflare) report the socket's public address. Logged; the user is warned when the carrier changes the address per destination (then nothing on the phone can fix it; Wi-Fi usually works) or when the registry recorded a different address. `NodeRuntime.RunNetworkCheckAsync`, `LastNetworkCheck`. LiveCheck: `netcheck` and `register --iax`.
- **Honest registration badge:** `NodeRuntime.IsRegistered` now also requires a successful registration within 2 intervals + 30 s; otherwise `RegistrationLapsed` is true, the status says "Registration lapsed … re-registering", and the UI tick calls `RenewIfLapsed()`.
- **Android idle registration:** with no link the service holds no wake lock, so the CPU slept and the registration timer stopped (the report shows ~20 minutes without a refresh). `RegistrationAlarm` wakes the app every 2 minutes while idle (Doze stretches this to ~9 minutes) to re-register under a short wake lock.
- **HTTPS registration** no longer reuses a pooled connection (one opened over cellular kept going out over cellular after joining Wi-Fi).
- **Pre-existing broken test fixed:** `EarlyHangupAfterAccept_IsRetried_UntilTheRemoteAccepts` failed on the unchanged code too (its 300 ms pause outlasted the 200 ms attempt timeout); the pause is removed.
- Validation: 700 Core tests and 18 headless UI tests pass; full solution builds. `netcheck` run live from the owner's PC: Consistent (both STUN servers saw 108.65.179.71:51490). **Not verified:** IAX2 registration against the real register.allstarlink.org (needs the node password), anything on a phone or on Tom's carrier, the Android alarm.

## 2026-11-12: linked nodes "randomly" dropping (1.17 / code 19)

Owner report: on the latest install a linked node (523800) would later be gone. The log excerpt supplied shows six nodes all hanging up about 100 ms after accepting, straight after a network change, with Wi-Fi lost again 9 s later; it does not include the moment a node was removed, so the cause on the phone is **not confirmed**. Four ways a node could vanish or be mis-handled were found in the code and fixed or made visible:

- **An established link whose far end hung up was never redialled.** It is now redialled (back-off, at most 5 drops in a row, fresh count after 5 minutes up) unless the far node sent app_rpt's `!!DISCONNECT!!` first, which is how app_rpt itself tells a deliberate unlink from a dropped call (read from the app_rpt source; PROJECT_SPEC §5.6).
- **Early-hangup retries were shared across network changes**, so a phone hopping between Wi-Fi and cellular could run a node out of its 30 retries. A real network change now restarts the count.
- **One hang-up could be counted as two retries** when it landed just as a reconnect finished. A call's end is now handled once.
- **"Audio could not start: Object reference not set to an instance of an object"** (in the owner's log): the audio engine's start raced its disposal on a call that was hung up at once. Start/stop are now mutually exclusive; the new test fails with that exact exception on the old code.
- **Logging:** every node that leaves the list now logs why, and the Android car service logs every audio-focus change.
- **Owner decision, implemented:** a media Pause/Stop command (car screen, steering wheel, headset, Bluetooth stereo) or another app taking the audio **mutes** the linked nodes instead of hanging the car's node up (a silent hang-up looked like a node dropping by itself). Play unmutes and takes the audio back; per-node Disconnect remains the way to hang up from the car. Rules are in `CarMediaButtons` with updated tests; not tried in a car.
- Validation: 692 Core tests pass (the runtime/audio groups five times in a row); Android head builds. **Nothing here has been run on a phone or against a live node.**
