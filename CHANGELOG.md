## 2026-11-22: 1.30 / code 33

- **Fix IAX2 registration Step 1 against `register.allstarlink.org` (from v1.29 AT&T phone log):** Tom's v1.29 log showed AT&T CGNAT giving his UDP call socket one consistent public IP across both STUN servers (`74.254.84.65`), while IAX2 registration got `REGAUTH` on Step 0, timed out on Step 1 (`4 request(s)`), and fell back to HTTPS (`74.254.78.54`), causing `RegistryMismatch` and immediate remote hangups. Live probes against all three `register.allstarlink.org` IPs revealed why:
  - `Iax2Registrar` sent an explicit `ACK` after `REGAUTH` before sending the authenticated second `REGREQ`, which caused `register.allstarlink.org` to tear down the pending transaction and answer Step 1 with a malformed `F=0` frame that was silently discarded; per RFC 5456 §6.1 / `chan_iax2`, the second `REGREQ` implicitly ACKs `REGAUTH` via `ISeqno`.
  - `register.allstarlink.org` sends `REGAUTH` with `ISeqno = 0`, so copying `f.ISeqno` left our Step 1 `REGREQ` at `OSeqno = 0` instead of `1` (`oseq` now advances cleanly on `REGAUTH`, `REGACK`, and `REGREJ`, with `CallToken` omitted on Step 1 unless issued and retransmitted `REGAUTH` frames ignored).
  - `Iax2Registrar` now parses numeric `CauseCode` IEs (reporting e.g. `"Registration rejected (IAX2): code 29"` when no text `Cause` IE is present) and includes the last received frame and pinned server IP when a multi-step exchange times out.

## 2026-11-19: 1.21 / code 23: links refused on carrier NAT ("does not match link IP"); lapsed registration

Field report: Tom (node 41603, NodeX on 5G) could not link to 41605/41604. The far nodes logged `Node 41603 IP 74.254.145.15 does not match link IP 74.254.149.17` (app_rpt drops a caller whose IP differs from the registered one) and, at other times, `Reported node 41603 cannot be found` (registration had lapsed while the badge still said "ASL Registered").

- **One shared UDP socket for calls and registration** (`Iax2Endpoint`). Every call now runs on it (`Iax2Session(Iax2Endpoint)`; distinct call numbers; datagrams dispatched by sender, unknown senders dropped), and the node **registers over IAX2** (`Iax2Registrar`: REGREQ/REGAUTH/REGACK, like an Asterisk `register =>` line) from that same socket, so the registry records exactly the public address the calls leave from. Before, registration went over HTTPS (TCP) and each call had its own UDP socket, and a carrier NAT can give each a different public address. New setting `IaxRegistration` (default on; no UI) replaces the old experimental `UdpRegistration`. `FallbackRegistration` switches to HTTPS if IAX2 never gets an answer (two attempts) or is rejected on this network; only one of the two runs at a time. A network change opens a fresh socket and restarts registration on it; calls on the old socket keep it until they end.
- **Registrar hardening:** each request is re-sent twice before counting as "no reply", one unanswered attempt is tolerated while registered, quick doubling retry after no reply, a background loop with out-of-band refresh like the HTTPS one.
- **Re-register before dialling** when the registration has lapsed, or (IAX2) is older than 20 s (`ReconnectPolicy.PreDialRegistrationAge`), waiting up to `RegistrationWait` (5 s). This brings back a short pre-dial wait in those cases (typically a few hundred ms), unlike the 15 s settle wait removed in 1.18.
- **NAT keep-alive:** while registered over IAX2, a STUN request every 25 s keeps the socket's carrier mapping (and so its public address) alive between registrations; if the public address changed anyway the node re-registers at once.
- **Network check** (`NetworkCheck`): after the first registration on each socket, two STUN servers (Google, Cloudflare) report the socket's public address. Logged; the user is warned when the carrier changes the address per destination (then nothing on the phone can fix it; Wi-Fi usually works) or when the registry recorded a different address. `NodeRuntime.RunNetworkCheckAsync`, `LastNetworkCheck`. LiveCheck: `netcheck` and `register --iax`.
- **Honest registration badge:** `NodeRuntime.IsRegistered` now also requires a successful registration within 2 intervals + 30 s; otherwise `RegistrationLapsed` is true, the status says "Registration lapsed … re-registering", and the UI tick calls `RenewIfLapsed()`.
- **Android idle registration:** with no link the service holds no wake lock, so the CPU slept and the registration timer stopped (the report shows ~20 minutes without a refresh). `RegistrationAlarm` wakes the app every 2 minutes while idle (Doze stretches this to ~9 minutes) to re-register under a short wake lock.
- **HTTPS registration** no longer reuses a pooled connection (one opened over cellular kept going out over cellular after joining Wi-Fi).
- **Pre-existing broken test fixed:** `EarlyHangupAfterAccept_IsRetried_UntilTheRemoteAccepts` failed on the unchanged code too (its 300 ms pause outlasted the 200 ms attempt timeout); the pause is removed.
